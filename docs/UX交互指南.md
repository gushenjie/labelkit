# 视炼 UX 交互指南

适用范围：项目、数据、任务、模型、素材、标注、复查和训练。视觉基础仍以《UI设计规范》为准；本指南定义行为、反馈及动效。首批实现公共组件与任务中心，其余页面专属流程按接入清单推进，不能把规范中的目标状态当作已经实现。

## 1. 设计目标与优先级

用户需要确认操作已接收、识别发生的变化、持续找到关注对象，并区分实际结果与处理中。信息静止不是缺陷；不为静态标签、未变化的数值或后台每次轮询播放动画。

反馈优先级：阻止错误操作 > 用户主动操作 > 当前对象的重要状态变化 > 后台局部更新 > 入场装饰。发生冲突时高优先级立即生效，旧动画取消，不排队播放。工具主体采用功能动效，视图切换可以有明确的空间连续性；不做文字拉伸、整屏弹跳、循环状态发光。

## 2. 节奏与实现基础

| 类型 | 默认时长 | 用途 |
|---|---:|---|
| feedback | 120ms | 可操作状态的颜色、边界反馈 |
| enter | 180ms | 下拉、提示进入；内容位移最多 4px |
| exit | 160ms | 弹层、通知和离开结果的退出上限 |
| layout | 280ms | 用户触发的视图位置交接 |
| data | 320ms | 数值替换、进度条达到新值 |
| 弹框内容 | 220ms | 内容进入最多 8px，遮罩只淡入 |

CSS 变量使用 `--lk-motion-*`，脚本使用公共 `motion` 常量，缓动统一 `cubic-bezier(.22,1,.36,1)`。两处是同一组默认值，变更须同步。时长不延迟业务状态，不作为人为等待。

优先 CSS 与 Web Animations API；不逐帧更新 React state。布局读取成批执行，只处理可见对象，动画结束不保留 transform。持续加载动效仅用于等待数据，使用同步低幅度 opacity，加载完成即停止；普通状态不循环。

## 3. 控件与操作契约

| 场景 | 行为要求 |
|---|---|
| 按钮 | 默认、hover、focus、按下、禁用、提交中均可区分；点击后立即显示处理中，尺寸稳定，重复操作不重复提交 |
| 表单 | 本地可判断的必填/格式条件决定可提交状态；键盘与点击遵守同一条件；失败保留输入，恢复重试 |
| Select | 触发器保留焦点，方向键/Home/End 跳过禁用选项，Enter 选择，Esc/Tab 收起；退出内容 inert、不可点击 |
| 分段切换 | 标签不移动，选中标识可以移动；方向键/Home/End 切换并移动焦点 |
| 确认框 | 业务结果只兑现一次；打开后约束焦点，关闭归还来源；旧退出不能关闭新弹框 |
| Toast | 用户操作结果用短通知；有明确行动时提供入口；退出即禁用操作；不对每条后台完成结果弹通知 |
| 导航 | 当前页面标识立即更新；保持壳层稳定，目标区域加载有占位；不跨页面重播相同卡片入场 |

弹层的逻辑打开状态与视觉存在状态分离。退出显示只读快照，不继续处理业务；用户提交成功后不等待动画才开始下一步。弹框内部滚动，背景锁定滚动；多个弹框按栈处理键盘与焦点。提交期间关闭策略由业务明确传入，不能仅由动画决定。

## 4. 数据、列表和长任务

- 数字显示服务端真实值，通过替换过渡提示变化，不计数经过未返回的数据。没有总数显示“—”，不伪造进度百分比。
- 进度条可以从旧值插值到新值；百分比、状态和操作权限立即反映新数据。相同数据无动画。
- 初次加载用最终布局相近的骨架和数值占位。初次失败展示可重试错误，不能显示为空列表。后台刷新失败保留旧数据并标明状态。
- 筛选、分页是用户操作，取消旧转场并立即展示新结果；后台更新保留未变化对象。任务离开筛选时立即 inert，最多保留 160ms 退出，结果数使用最新数据。
- 列表与卡片通过任务 ID 保持身份；以首个可见任务和顶部偏移恢复滚动，受新滚动范围约束。部分可见对象在尺寸缩小时至少保持可见。身份区域只平移，不缩放文字；数据字段按新布局即时就位。
- 用户滚动、调整视口、改变筛选或再次切换时取消旧动画；禁止动画完成回调恢复过时状态。
- 续训/编辑表单只在打开新对象时初始化，不被轮询对象替换覆盖。失败后保持输入；提交中防止重复触发。
- 标注画布的拖拽、缩放、选框直接跟随输入，不加入缓动延迟。保存、撤销、复查确认和训练阶段改变在相关区域反馈，不移动画布。

## 5. 无障碍与降级

遵守 `prefers-reduced-motion`，完整显示终态，停止位置过渡和加载循环，保留语义、文案、焦点环。动画没有完成也不能阻断关闭或重试。退出副本从无障碍树与键盘顺序移除。不要把整个轮询列表设为 live region，避免重复朗读所有任务。

第一阶段仅 PC：主验收 1440×900，兼容 1920×1080、1366×768；手机端适配与验收留待后续阶段。卡片状态、时间、操作区按同一轨道对齐，无按钮卡片也保留操作轨道。

## 6. 接入与验收

公共入口：`Presence` / `ModalSurface` / `ChangedValue`；有离场要求的列表使用 `useExitItems`。任务中心布局定位为业务 hook，不推广为全站默认动画。

开发环境 `/dev/ux` 提供真实公共组件样例；生产环境返回 404。样例不调用业务 API。回归命令：在 web 下运行 `npx playwright test --config playwright.ux.config.ts`；全部 API 由测试拦截，录像、截图、trace 和 JSON 报告输出到 `web/artifacts`。测试数据不能代替真实业务数据验收。

准入门槛：十次快速切换后终态正确；中途滚动可打断；卡片纵向对齐误差 ≤1px 且按钮不越界；未知总量不显示假值；无变化的轮询不重播；失败保留输入；重复确认只发生一次；关闭后立即重开无旧回调干扰；键盘及减少动态效果可用；预热后动作观测窗口内无 >50ms 长任务。性能结果只对记录设备与场景有效，不推断所有设备均通过。

视觉评审检查对象是否可追踪、变化是否可察觉、是否打扰阅读，并保存录像；代理评审通过不代表用户已认可主观风格。详细结果见《UX交互验证记录》。
