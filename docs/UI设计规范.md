# LabelKit UI 设计规范

> 版本：1.0  
> 状态：当前产品 UI 的实现基线  
> 适用范围：项目列表、项目工作台、素材、标注、复查、训练、任务、设置等全部 Web 页面

## 1. 设计主张

LabelKit 采用「精密数据工作台」作为统一视觉概念：

- **项目和数据是主角**：界面用于提升扫描、判断和操作效率，不用装饰抢注意力。
- **高密度但不压迫**：通过稳定对齐、轻边界和密度节奏承载专业信息。
- **绿色只表达确定性**：品牌、主操作、进度和成功状态使用绿色；普通信息保持中性。
- **表面轻、层级清楚**：白色面板、冷灰画布、1px 边界和极浅阴影构成空间，不使用厚重卡片。
- **交互像精密仪器**：反馈短、准、稳，不使用弹跳、强发光或大幅缩放。

用户第一次进入时应记住：这是一个清楚、可信、能掌控复杂标注流程的专业工具。连续使用时应感到信息容易扫描，状态容易判断，主操作始终明确。

## 2. 设计 Token

代码中的唯一事实源位于：

- CSS 变量：`web/src/app/globals.css`
- Tailwind 映射：`web/tailwind.config.ts`

### 2.1 色彩

| Token | 色值 | 用途 |
|---|---:|---|
| `--lk-brand-50` | `#ECFDF8` | 品牌浅背景、选中态 |
| `--lk-brand-500` | `#12A88F` | 品牌高亮、进度 |
| `--lk-brand-600` | `#07947D` | 主按钮、选中控件 |
| `--lk-brand-700` | `#087866` | Hover、深色品牌文字 |
| `--lk-ink` | `#101828` | 标题、关键数字 |
| `--lk-text` | `#344054` | 正文、控件文字 |
| `--lk-muted` | `#667085` | 次级说明 |
| `--lk-subtle` | `#98A2B3` | 占位、弱提示 |
| `--lk-border` | `#E4E7EC` | 普通边界、分隔 |
| `--lk-border-strong` | `#D0D5DD` | 输入框、按钮边界 |
| `--lk-surface` | `#FFFFFF` | 面板、卡片 |
| `--lk-surface-soft` | `#F7F9FB` | 工具栏、Hover |
| `--lk-canvas` | `#F8FAFB` | 页面画布 |

语义色：

- 成功：背景 `#ECFDF3`，文字 `#079455`
- 警告：背景 `#FFFAEB`，文字 `#DC6803`
- 错误：背景 `#FEF3F2`，文字 `#D92D20`
- 信息：背景 `#EFF8FF`，文字 `#1570EF`
- 图像分类：背景 `#FFF6ED`，文字 `#C4320A`

约束：

- 同一屏大面积高饱和色只能出现于主按钮。
- 品牌绿不能用于普通正文或纯装饰。
- 红色只能表示错误、危险和删除。
- 不使用黑色大面板、霓虹发光和多重彩色渐变。

### 2.2 字体

字体栈：

```css
-apple-system, BlinkMacSystemFont, "SF Pro Text", "PingFang SC",
"Microsoft YaHei", "Noto Sans CJK SC", Arial, sans-serif
```

| 层级 | 字号 / 行高 | 字重 | 用途 |
|---|---|---:|---|
| 页面标题 | 26 / 40 | 700–730 | 一级页面名称 |
| 区块标题 | 14 / 20 | 650–680 | 面板、列表分组 |
| 关键数据 | 18–21 / 26 | 700 | 汇总指标 |
| 正文 | 13–14 / 20 | 400–500 | 表单、说明 |
| 列表主信息 | 14 / 20 | 650–680 | 项目名称 |
| 辅助信息 | 10–12 / 16 | 400–500 | 元数据、提示 |

中文正文不使用小于 10px 的可操作文本。数字保持等宽视觉节奏，不为装饰使用超粗字重。

### 2.3 圆角、边框、阴影

| Token | 值 | 用途 |
|---|---:|---|
| `--lk-radius-xs` | 4px | Badge、分页 |
| `--lk-radius-sm` | 6px | 输入框、按钮 |
| `--lk-radius-md` | 8px | 小卡片、提示 |
| `--lk-radius-lg` | 10px | 主面板 |
| 普通边框 | 1px `--lk-border` | 面板、分隔 |
| 强边框 | 1px `--lk-border-strong` | 输入框、次按钮 |
| `--lk-shadow-panel` | 极浅双层阴影 | 常驻面板 |
| `--lk-shadow-hover` | 轻浮起阴影 | 可点击卡片 Hover |

禁止：

- 12px 以上的大圆角用于密集业务表格。
- 同一组件同时使用粗边框、重阴影和强背景。
- 用阴影代替必要的边界和状态。

### 2.4 间距

基础单位为 4px。优先使用 `4 / 8 / 12 / 16 / 20 / 24 / 32`。

- 页面水平安全边距：桌面 34px，平板 18px。
- 主区块间距：12–14px。
- 面板内边距：16–20px。
- 表单项垂直间距：16px。
- 密集列表行高：72–92px，按信息量选择。
- 图标与文字间距：6–9px。

## 3. 页面骨架

### 3.1 全局顶栏

- 桌面高度 74px，移动端 64px。
- Logo 位于左侧，主导航紧随其后，全局动作在右侧。
- 当前导航项使用 2px 品牌绿底线，不用整块高亮。
- 顶栏吸顶，背景保持 94% 白色并使用轻微模糊。

### 3.2 内容区

- 最大宽度 1720px，居中。
- 页面标题、说明和主操作组成 Page Header。
- 每页只能有一个主按钮；危险操作不得与主按钮同权重。
- 复杂工具页优先使用稳定工具栏 + 主内容，不平均铺满卡片。

### 3.3 项目首页三栏结构

桌面宽度大于 1240px 时：

```text
┌──────────────────────── 概览统计 ───────────────────────┬──── 最近活动 ────┐
├──── 筛选 210px ────┬──────── 项目列表（主角）──────────┤──── 快捷入口 ────┤
│                    │                                  │──── 存储使用 ────│
└────────────────────┴──────────────────────────────────┴──────────────────┘
```

- 左栏只处理筛选和保存视图。
- 中栏必须获得最大视觉权重。
- 右栏只提供即时动态与跨流程入口。
- 右栏在中等视口移动到列表下方，不压缩主列表到不可读。

## 4. 组件规范

### 4.1 Button

主按钮：

- 高度 38–40px，圆角 6–7px。
- 品牌绿背景、白字、仅允许一个页面主操作。
- Hover 轻微加深并增加阴影；Active 下移 1px。

次按钮：

- 白底、强边框、中性色文字。
- 不用灰色实心按钮与主按钮竞争。

图标按钮：

- 标准尺寸 30px 或 34px。
- 必须提供 `aria-label`。
- 图标使用 1.7px 线宽，保持同一套视觉语言。

### 4.2 Input / Select

- 高度 38px；密集工具栏可用 30px。
- 白底、1px 强边框、6px 圆角。
- Focus 使用品牌边框 + 3px 低透明度外环。
- Placeholder 使用 `--lk-subtle`。
- 错误状态必须同时有错误文字，不能只靠红色边框。

### 4.3 Panel / Card

- 主面板使用白色、10px 圆角、1px 边界和 `--lk-shadow-panel`。
- 复杂内容优先在一个面板内用弱分隔组织，不把每行都做成独立厚卡。
- 可点击卡片 Hover 应同时提供边界/背景或轻微阴影变化。

### 4.4 Badge / Status

- 任务类型使用矩形浅色 Badge，4px 圆角。
- `目标检测` 使用绿系；`图像分类` 使用橙系。
- 运行状态使用“圆点 + 文字”；状态不能只依赖颜色。
- 状态文案统一：进行中、已完成、已暂停、待开始、失败。

### 4.5 数据列表

- 表头使用 10–11px 次级文字与浅灰背景。
- 行主标题、说明、元数据形成三级信息层级。
- 数量使用千分位。
- 进度同时展示百分比、进度条和完成数/总数。
- 行 Hover 使用非常浅的品牌背景和左侧 3px 品牌指示，不做大幅位移。
- 每行固定提供一个明确主动作，其他操作放入更多菜单。

### 4.6 空、加载、错误状态

- 加载使用与最终布局同形的骨架屏，避免布局跳动。
- 空状态包含图标、标题、解释和一个下一步动作。
- 错误状态包含清晰原因和“重试”，不把错误吞掉。
- 图片容器必须预留稳定尺寸，使用 `object-fit: cover`，不得拉伸。

### 4.7 Modal / Dialog

- 用于不需要离开当前上下文的创建、编辑和确认流程；复杂的多步骤任务仍应使用独立页面。
- 桌面弹框宽度优先使用 560–720px，最大高度不超过视口减 48px；内容区独立滚动，头部和底部固定。
- 遮罩使用中性深色 40%–45% 透明度与轻微模糊，不使用高饱和品牌色遮罩。
- 头部必须包含明确标题、简短目的说明和关闭按钮。
- 底部操作顺序为“状态/错误信息 → 取消 → 主操作”，主操作仍遵守全页唯一原则。
- 支持点击遮罩、关闭按钮和 `Esc` 关闭；提交过程中禁止意外关闭。
- 打开后焦点进入第一个可编辑字段，`Tab` 焦点不得逃出弹框，关闭后背景恢复滚动。
- 小于 430px 时允许弹框全屏显示，表单从横向布局切换为单列。

## 5. 动效与反馈

- 常规 Hover / Focus：150–160ms。
- 页面或大面板进入：如需使用，控制在 180–220ms。
- 缓动：`cubic-bezier(0.22, 1, 0.36, 1)`。
- 只动画 `opacity`、`transform`、颜色、边框和阴影。
- 尊重 `prefers-reduced-motion`。
- 不使用持续脉冲、大幅缩放、弹性回弹或同时上演的多组入场动画。

## 6. 响应式

| 断点 | 行为 |
|---:|---|
| `> 1240px` | 三栏项目工作台 |
| `981–1240px` | 右栏移到主内容下方 |
| `721–980px` | 单列主布局，项目列表转卡片 |
| `≤ 720px` | 隐藏高级筛选，主按钮收为图标，右栏纵向堆叠 |
| `≤ 520px` | 概览指标单列，工具栏隐藏低优先级控件 |

移动端仍需满足：

- 无横向页面溢出。
- 点击目标不小于 36px；核心操作不小于 40px。
- 表格在窄屏转换为卡片，而不是强行压缩文字。

## 7. 页面实现准入清单

新增或改版页面在合并前必须确认：

- [ ] 使用全局 `app-header`、`app-main` 和颜色 Token。
- [ ] 页面只有一个主操作。
- [ ] 标题、正文、辅助文字层级符合字体规范。
- [ ] 面板、按钮、输入框没有私自新增圆角和阴影体系。
- [ ] 状态同时使用图形/文案，不只靠颜色。
- [ ] 已实现 loading、empty、error 中实际需要的状态。
- [ ] Hover、Focus Visible、Disabled 有反馈。
- [ ] 桌面和窄屏真实渲染无溢出、遮挡。
- [ ] 3 次及以上重复结构已评估是否提取组件。
- [ ] 动效不干扰长时间标注和读数。

## 8. 复用边界

当前全局基础组件类：

- `.card`
- `.btn` / `.btn-primary` / `.btn-secondary`
- `.input`
- `.badge`
- `.icon-button`

图标组件：

- `web/src/components/Icon.tsx`

业务弹框：

- `web/src/components/CreateProjectModal.tsx`

页面专用结构可保留局部样式；当同一结构在 3 个页面重复后，再抽取为通用组件。不要为了单次使用创建过度抽象。

## 9. 禁止模式

- 深色默认后台、黑底大卡片。
- 通用 SaaS 四宫格平均布局。
- 大面积品牌绿或橙色。
- 玻璃拟态、霓虹发光、重渐变。
- 所有区块同等大小、同等重量。
- 过厚边框、过重阴影、过多分割。
- 使用 Emoji 代替产品图标。
- 没有 Focus、空态、错误态或移动端策略的“静态稿式实现”。
